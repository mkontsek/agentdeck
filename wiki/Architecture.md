# Architecture

`AppStore` owns sessions, board, runtime status and orchestration on the main actor; `TerminalHost` owns SwiftTerm PTYs; `BrowserHost` owns WebKit profiles. Views render these resources and never start processes or recreate stopped browsers. macOS 14+, SwiftUI.

## 1. Repository structure

| Location | Responsibility |
| --- | --- |
| `Sources/App`, `Sources/Views` | lifecycle, menus, SwiftUI surfaces |
| `Sources/Store` | session lifecycle, board, persistence, injection |
| `Sources/Models` | persisted value types, runtime models |
| `Sources/Terminal`, `Sources/Browser` | native resource owners and view adapters |
| `Sources/Services` | git subprocesses, literal shell placeholders, status heuristics |
| `Sources/Services/SkillScanner.swift`, `Sources/Store/SkillLibrary.swift` | bounded skill discovery, enabled catalog, cached instructions |
| `Sources/MCP` | HTTP framing, loopback listener, JSON-RPC, tools |
| `Tests` | isolated regression and local integration tests |
| `.githooks` | opt-in pre-commit gate |

## 2. Processes and shell

- Git runs on a background queue with file-backed stdout/stderr, so a full pipe cannot deadlock and diagnostics stay separate.
- Worktree creation failure stops session creation. Dirty worktree deletion fails and keeps the session. Deletion refuses paths another session references and passes `--` before the path.
- Shell templates expand placeholders as literal values in unquoted, single-quoted and double-quoted contexts, escaping by Unicode scalar. Templates themselves are trusted code. Use environment variables for nested substitutions and here-documents.
- Built-in commands carry the provider's permission-bypass flag. Legacy state is upgraded only for exact previously shipped commands; the persisted `unrestrictedCLIDefaultsApplied` marker makes it one-time. Custom commands, plain shells and running processes are untouched.

## 3. Injection and briefing

- Background coordination never writes to a PTY. `Services/CoordinationInbox.swift` atomically journals published events in `coordination-inbox.json`; `MCP/InboxTools.swift` automatically attaches pending events to tool results. `read_inbox` / `acknowledge_inbox` provide explicit receipt. A stopped/idle provider retains its mailbox; no focus, idle, quiet-time or terminal-text heuristic authorizes delivery into a composer.
- Events bind to the managed-session UUID, CLI profile and working directory. Pending → offered → acknowledged describes receipt only, never processing or task completion. Lost responses reoffer the same IDs; sender `message_id`, handoff UUIDs and task revisions deduplicate retries. Removed sessions never redirect events to replacement tabs. An asynchronous tool response checks the caller's process generation before attaching events. Corrupt or full journals fail acceptance visibly and preserve existing records.
- Fresh built-in initial tasks travel as provider prompt arguments before a composer exists. Custom templates opt in with `{initialPrompt}`; unsupported templates queue the task/briefing pointer instead of typing it. Resume/restoration never replays initial tasks.
- The briefing is written before launch (`briefing/<id>.md`). Claude uses `--append-system-prompt-file`; Codex uses TOML-encoded `developer_instructions`; Grok uses additive `--rules`. Both fresh and resume templates carry instructions across conversation resets. Placeholders encode payloads as literal shell arguments, with a separate TOML encoding step for Codex.
- Gemini and Antigravity receive a persistent bootstrap section in `~/.gemini/GEMINI.md`, preserving existing content. It tells the agent to read its own `AGENTDECK_BRIEFING` after fresh/resumed/cleared conversations; no shared session identity is written into global rules. The section is inactive outside AgentDeck. Tests redirect this write to an isolated provider home. Custom profiles without a persistent mechanism retain a briefing pointer in their startup argv or inbox.
- `resumeLastConversation` controls only first-launch directory continuation. `resumeOnRestart` defaults on independently, including for fresh tabs. `Store/SessionResume.swift` checkpoints Claude/Codex/Grok identities from bounded PID metadata/open-file paths on a utility task; transcript bodies are not read by this tracker. Normal quit awaits a final capture before disposing PTYs. Atomic `resume/<managed-id>.json` sidecars survive the older host's state writer during an upgrade.
- Restart prefers the pane's exact provider conversation, with directory/profile checks, file-existence checks, generation guards and ambiguous-match rejection. Unknown or missing exact history starts fresh without replaying the original task. A restored conversation receives no typed briefing. Custom templates are not rewritten; Gemini retains a single-pane best-effort fallback.
- Task60’s negotiated SwiftTerm `pasteText` plus separate delayed carriage return remains for explicit user Send Input actions only. Its terminal identity/generation guards remain. It proved empty-prompt paste handling, not draft safety; task79 removes all background callers from that path. No retry keys, clipboard draft capture, or approval-prompt automation are used.
- Status summaries enter the inbox only on explicit request (menu, pane menu, inspector) or inside the start-up briefing. There is no periodic broadcast.

## 4. State and rendering

- PTY output never publishes store state. `TerminalHost` records timestamps privately; the one-second tick folds them into `runtime` and republishes a session only when it changed.
- `TerminalMetadata` retains only the latest title/program values per session and batches changed presentation fields into one runtime publication per 100 ms. Identity and generation checks reject replaced terminals; stop/shutdown cancel pending updates. Native PTY output and task coordination bypass this presentation queue.
- The stats strip stays stable across focus changes. Compact panes omit auxiliary chrome according to window size, never focus.
- State writes are atomic. `AppStore(stateURL:)` lets tests use temporary state and MCP-config directories. An unreadable state file disables saving for that instance, surfaces an error and is preserved.
- Startup loads the skill catalog off the main actor, then restores sessions. With no sessions and the option on, `DefaultSessions` seeds one interface per provider: Claude Code, Codex, Antigravity, Grok Build, Perplexity; Gemini CLI replaces a missing Antigravity profile, browsers replace missing CLI profiles. The empty-canvas action uses the same idempotent seeding. Corrupt state blocks seeding. Shells and custom URLs are never defaults.
- A native `FocusClickView` covers inactive pane content, consumes the first mouse sequence and focuses the pane; it is removed once focused. Headers and resize grips stay interactive.
- Drag and resize measure translation in global coordinates. `PaneGridView` reports its viewport; `CanvasLayout` computes balanced rows for explicit Fill Canvas and the first windows in an initially empty workspace. Restored sessions retain their saved canvas positions and sizes independently of viewport dimensions; missing positions are placed without repacking existing panes. `saveNow` snapshots a measured grid's unmaximized frames into the existing canvas fields in the persisted copy, leaving the live grid untouched. Restart opens that snapshot in canvas mode. Legacy grid saves without displayed frames retain their last stored canvas geometry. Off-screen panes are revealed by scrolling, not repositioning. `SessionOrdering` puts Claude CLI first and Codex second for loading, creation, Tidy and Fill, independent of focus and z-order.
- `Views/WindowChrome/MiniWindowResizeOverlay` uses native grip-only hit testing above terminal/browser content, with a resize cursor only on the bottom-right 28-point grip. Mouse deltas use stable window coordinates; `WindowResizeGeometry` anchors the opposite edge and enforces minimum sizes. Starting a grid resize saves every displayed frame and switches to Canvas without replacing native views. CLI usage starts from its displayed, viewport-clamped frame and keeps the resized panel inside the viewport.
- `CanvasBackground` draws 2-point white dots on a dark background at a 16-point pitch, matching the website. It remains visible in both Grid and Canvas, uses dark dots in light appearance, and increases contrast with the system preference.

- `Store/PanePresentation.swift` derives effective font size from displayed pane dimensions (including grid/maximize), automatically capped at the configured global size with a 5-point minimum. Geometry is the stable scale reference, so returning to an earlier small size restores its earlier font; manual overrides retain their 5–40 point range. Existing `fontSizeOverride` values stay fixed; clearing an override restores scaling. BrowserPageFit instead measures document width in an isolated WebKit content world after navigation and viewport resize, then adjusts pageZoom to fit width. Manual zoom overrides remain fixed. Debounced measurements are generation/viewport/URL guarded and never modify site content or profiles.
- `CanvasScrollObserver` observes only the canvas clip view. During scrolling or typing and their 120 ms quiet tail, background terminals defer display invalidations and retain their native layer contents. Off-screen panes keep deferring until visible. The keyboard responder always stays live. Deferred drawing catches up once; parsing, input, process ownership and accessibility text are unchanged. Observer teardown restores drawing. No page JavaScript, renderer replacement or dependency patch is involved.
- The same native observer reports document/visible rectangles and current pane frames to a separate `CanvasOverviewState`, owned but not published by `AppStore`. Only `CanvasMiniMapView` at the bottom of the Sessions sidebar observes it. Updates coalesce within a main-queue turn, compare snapshots before publication and use attachment IDs so old callbacks/teardown cannot replace a newer canvas. Geometry is transient, aspect-fitted and validated; no terminal text or browser content enters the map. `CanvasMiniMapInteraction` preserves a drag's viewport grab offset, unprojects map coordinates and invokes a navigation callback bound to the current observer/snapshot. The native clip view constrains scrolling. The snapshot retains an unclipped viewport for drag geometry separately from its clipped drawing rectangle; sub-half-point size rounding is tolerated so a pan does not cancel itself. Source, canvas/map bounds and real viewport-size changes invalidate stale gestures. Pointer and accessibility navigation never request focus or publish the global workspace.

## 5. Panes and tabs

- `SessionPane` groups the flat session list by persistent `paneID`. Ordinary CLI tabs may share a pane; each attached worker has its own pane and each browser owner's tabs share its CLI pane. Session UUIDs, parent/task roles, MCP routes, PTYs, provider checkpoints and WebKit profile IDs remain independent of geometry.
- `Store/ConnectedPanes.swift` repairs legacy nesting before hosts start, and enforces the same ownership boundaries when adding sessions. It changes presentation fields only, preserves valid pane IDs after closing a first tab, retains legacy active-browser hints, and removes stale pane selections. Repeated load/save is idempotent. No layout migration launches or disposes a host.
- `BrowserPresentation` resolves the visible owner/browser pair. A per-owner `browserSplitEnabled` flag defaults true, including older saved sessions; stable native session keys keep the terminal attached while focus moves between the pair.
- `browserSplitFraction` saves the terminal's share per CLI owner (legacy default 50%, clamped to 10–90%). `BrowserSplitGeometry` applies adaptive minimum sizes without rewriting that preference. A native divider uses stable window coordinates, previews through local SwiftUI state and commits once on release; owner, visible-session, axis, size or attachment changes invalidate the gesture. It never requests keyboard focus. The same retained layout supports side-by-side and stacked presentation.
- `glassBallSubagents` is an opt-in persisted presentation preference. `GlassBallPresentation` resolves eligible worker panes/status and click-based expansion follows explicit focus. `GlassBallDock` derives a stable edge midpoint from full worker/parent geometry, shared by sphere perimeter, route port and native layer scale anchor. `PaneGridView` supplies full reserved bounds plus docks to connectors and displayed compact bounds to the overview. `GlassBallTransitionView` scales/fades retained layers over 420 ms without resizing terminal geometry; other workspace motion remains 280 ms. A revision-guarded animation completion hides native content only after collapse. Native terminal/browser child autoresizing is held during the transform and while collapsed, avoiding fractional PTY/viewport reflow from scaled AppKit containers; expansion completion restores normal sizing. Reversal, disappearance and Reduce Motion invalidate older completions. Attention pulses the glow only. Terminal display deferral composes independently with canvas scrolling; PTY parsing continues and the newest screen paints on expansion. Focused panes remain expanded, and explicit selection unhides its native target before the existing focus request. There is no hover expansion handler. Main panes, maximized views and demo content remain full size.
- Demo mode is non-persisted presentation state. Opaque synthetic pane views receive only a sequential number and split/layout callbacks, never private content; live content stays retained but hidden, inaccessible and unfocused. Other private main-window panels are hidden without modifying their preferences.
- `selectedBrowserTabs` retains each agent’s last selected browser independently of window focus and other owners sharing an ordinary CLI tab group. Legacy separate browser panes migrate into their owners without replacing browser/profile/session IDs.
- `selectedPaneTabs` persists each window's active session. Sidebar, relationship navigation and tab shortcuts reveal the selected window and update the maximized view. New workers and background browser creation preserve focus. Pointer focus/drag does not trigger canvas scrolling.
- `sessionDisplayStatus` supplies the shared four-state presentation for glass balls, `SessionStatusIndicator` dots and tab icons, resolving owned browser tabs to their agent. Attention from runtime or task approval/blocking takes precedence, followed by working, confirmed completion and idle. Raw `SessionStatus` and MCP/status heuristics remain unchanged; diagnostic runtime details are explicitly labeled. Sidebar list selection uses `selectSidebarSession` to update pane selection/reveal without requesting native focus, allowing consecutive native Up/Down events. Return explicitly calls `focusSession`; no global keyboard monitor is installed.
- Position, size and z-order apply to all members of one pane. Removing the active tab selects a neighbor; closing the last tab removes that pane. Worker panes cannot create additional CLI tabs. Closing a parent promotes surviving workers without stopping their processes; the removed parent's own browser tabs close as before.
- `PaneTabBar` uses vertically scrolling rows (three visible, two below 400 points). Browser panes retain an add-tab control with one tab; Cmd-T creates a browser tab while a browser is selected. Each new browser tab inherits its source's owner/profile, and automation resolves only the caller's selected owned tab.
- `SessionTabs` clones an ordinary source's CLI, directory/worktree and font/launch preferences; not its initial prompt or orchestrator role. New CLI tabs start fresh and retain independent restart checkpoints, runtime, PTY, MCP URL and tasks.
- `PaneConnectionsView` draws right-angled directional parent → worker paths with small rounded bends above mini-window borders, with hit testing disabled. `PaneRouteSearch` prefers 12-point padded obstacles for both direct shortcuts and the orthogonal visibility grid; only endpoint departure/arrival segments may enter their own gutter. Exposed ports also respect neighboring gutters. When that spacing is impossible it retains the compact direct route or retries the grid at 3 points. `PaneRouteCache` reuses paths until geometry or relationships change. Covered endpoints have no visible path. Searches reject nonfinite geometry and stop above 128 obstacles/16,384 grid nodes per attempt to bound main-thread work. Persisted `arrowColorHex` controls the line/arrow color independently of the focus border; invalid/legacy values use the default warm brown. Paths follow movement/resizing and disappear while maximized. `PaneRelationshipBar` exposes the same relationships as labeled navigation buttons/menus, including in maximized mode; meaning never relies on color alone.
- Native move grips, title dragging and the bottom-right resize grip operate on individual panes. Window-action menus provide keyboard-accessible movement, size presets and maximize/restore. Grid resizing detaches at measured frames. `TerminalRepresentable` keeps the owned PTY alive when a tab is hidden; stable pane/view identity preserves native containers across layout and maximize changes.
- See [[Connected-Mini-Windows]] for migration, controls and regression evidence. Legacy split-layout values remain decodable but no longer control the interface.

## 6. Browser profiles and downloads

- `AppSettings.sharedBrowserProfileID` names one persistent WebKit data store per workspace. Each browser session persists a `BrowserProfileMode`: `shared` (default, including legacy) or `isolated`.
- `browserProfileID` stays the session's separate store, so upgrades and mode switches never delete old login data. `BrowserHost` resolves the effective store per web view.
- Popup creation returns a separate `BrowserController` web view built with the exact WebKit-supplied configuration. WebKit owns the initial request (including POST bodies), opener relationship, named-window reuse and explicit `noopener`; AgentDeck never reloads it into the parent or substitutes a profile.
- `BrowserPopupWindow` owns a transient native window displaying the committed origin without OAuth query parameters. The opener retains its children; script close, native close, parent disposal/restart and profile switches release the descendant tree, delegates and pending navigation waiters. Popups are not persisted sessions or MCP browser targets. Parent navigation remains independent.
- Popup navigation permits HTTP(S) and the initial `about:blank` document, and never launches an external application. A shared budget limits each session's entire descendant tree to eight windows. Requested sizes are clamped to the screen; script-opened windows do not become key until selected by the user. Existing download/upload delegates also serve children.
- Switching mode recreates only a running pane. Removing a shared pane never deletes the shared store; isolated-profile deletion refuses shared or referenced stores. No cookies are copied from Chrome or merged across profiles.
- Downloads use `AppSettings.downloadDirectory`; empty resolves to the Mac Downloads folder. `BrowserController` accepts a `WKDownload` for download navigations, unshowable responses and `Content-Disposition: attachment`. The name is one path component; collisions get ` (n)`; the folder is created on demand. Success is logged; failure is logged and alerted.

## 7. Agent browsers

- A one-time migration moves previously mandatory isolated companion panes into the existing shared profile, retaining each original separate-profile UUID and its stored data. A persisted migration marker preserves later user choices. Settings can make new companion panes isolated; existing panes choose their profile in the toolbar/inspector.
- `WKWebsiteDataStore(forIdentifier:)` provides persistent local storage; the shared UUID survives app restoration and agent removal. AgentDeck does not store passwords or merge/copy cookies across old profiles.
- `BrowserController` observes URL changes as well as navigation callbacks so client-side chat routes persist. Normal termination snapshots current browser URLs before saving; restart reuses each pane's retained website data store.

- The first `browser_*` call from a CLI session creates a companion session: `agentOwnerID` = the CLI, `shared` persistent profile by default (Separate account is optional), a browser tab in the owner’s pane, created without stealing focus or the selected tab.
- `Sources/Browser/BrowserAutomation.swift` implements the tools over the companion's `BrowserController`; `Sources/Browser/BrowserScripts.swift` holds the page scripts, each returning JSON.
- Tools act only on the caller's selected owned browser tab; browser sessions cannot call them. Companions are excluded from status summaries, listed with `agent_browser_of` in `list_sessions`, and removed with their owner; the shared profile is retained.
- `BrowserController` offers `navigate` (waits for the matching `WKNavigation`, 20 s timeout), `evaluate` (60 s deadline, resumed once, result as text/JSON) and `snapshot` (PNG).
- A hidden companion renders in an owned off-screen `BrowserAutomationPanel` that cannot become key or main and closes on disposal. It never joins the user's main-window responder chain: WebKit can clear that chain even when its own focus request is rejected. `BrowserFocusGuard` intercepts the public NSWindow responder boundary once, limited to owned `FocusProtectedWebView` targets. It rejects script/autofocus before AppKit can resign the existing editor. Native pointer/Tab dispatch and synchronous `focusSession` grant explicit focus; late representable attachment only fills an unclaimed responder chain. Other AppKit responders/windows pass through unchanged. The implementation uses Objective-C method exchange because WKWebView rejection alone occurs too late; native regressions exercise this boundary and ordinary browser/OAuth interaction. DOM focus and screenshots remain available to automation; companion occlusion detection is disabled. Creating a companion never temporarily focuses it or expands its worker tab.

## 8. Skill directories

- Settings persist root directories and disabled skill IDs (canonical manifest paths). Repository roots resolve conventional containers; a direct skills folder or single package also works.
- Scanning follows symlinks with canonical deduplication, but a manifest must resolve to a regular file inside a configured directory: a link into another configured folder passes, a link to `~/.ssh` is skipped with a warning.
- Build/vendor folders are skipped; depth, directory count, file size and total content are bounded. Scripts never execute.
- `SKILL.md` name/description frontmatter is parsed without a YAML dependency, including quoted scalars and folded/literal descriptions.
- `SkillLibrary` caches instructions, publishes UI state and writes an atomic Markdown catalog. Superseded reloads are cancelled; removed or disabled skills vanish from MCP immediately.
- Settings supplies folder-path input, search, individual toggles and bulk controls for the filtered list. Changing disabled IDs updates the catalog in place; only directory changes/reload rescan. Previously loaded agent context cannot be revoked by a toggle.
- `list_skills` exposes enabled metadata; `read_skill` accepts only an exact enabled ID. The catalog reaches agents through environment variables and the briefing. Provider configuration is unchanged; browser use is explicit copying.

## 9. Local MCP boundary

- `MCPServer` owns listener, connections and deadlines on the main actor. The parser rejects malformed or duplicate headers, negative or overflowing lengths and transfer encoding.
- Limits: 16 KiB headers, 1 MiB body, 64 connections, 15 s to receive a request. The deadline is cancelled once parsed so browser tools can wait, bounded by their own timeouts.
- One request per connection; the connection closes after the response, also on client half-close. Results are MCP content blocks; screenshots return an image block plus caption.
- Host and Origin must name the exact loopback endpoint; native clients may omit Origin. No wildcard CORS. Tool calls need a managed-session URL; recruit operations check the orchestrator role. Diagnostic GET endpoints stay local and readable.
- Session UUIDs identify callers and are **not credentials**: other local processes can read diagnostics and impersonate sessions. This is a trusted-local-machine boundary with no remote access.
- Transport: JSON over HTTP/1.1 with Content-Length. SSE, batching, chunked bodies and pipelining are unsupported.

## 10. Coordination workspace

- `Models/Coordination.swift` defines task states, monotonic task revisions, dependencies, completion approval, task events and persistent handoff packages. Older tasks decode with approval disabled; new tasks require it.
- `Store/CoordinationStore.swift` owns lifecycle and acceptance. Ownership stays with the sender until acknowledgment. The package snapshots only intentionally published task fields and supplied artifact references; no transcript or file scraping occurs.
- A handoff has independent approval/inbox-acceptance/recipient-acceptance states. Queued approved work is recovered on load; legacy in-flight delivery restores as failed and needs explicit retry. A delivered notification means durable inbox acceptance, not that a provider submitted or processed it. Recipient acceptance is idempotent and checks task revision, ownership, dependencies and user approval.
- `MCP/CoordinationTools.swift` enforces owner/orchestrator edits, unassigned claims, explicit transfers and participant-scoped package reads. Agents cannot approve gated completion. This is application policy on trusted-local identities, not authentication or a process sandbox.
- `Views/Coordination` provides the primary Work workspace, task detail/history and reviewable handoff composer. The existing session canvas is retained. Native terminal views remain mounted across Work/Sessions and use stable pane identities across grid/canvas/maximize transitions.
- `WorkspaceMotion` centralizes 240 ms transitions and respects Reduce Motion. Sheets retain standard macOS presentation; panels/disclosures/panes animate without creating replacement PTYs.
- `AgentStatusMenu` exposes attention/session status. `AttentionShortcut` owns its Carbon hotkey registration and unregisters on shutdown; registration failure is visible in the log.
- `Store/SubagentSessions.swift` and `MCP/SubagentTools.swift` provide `delegate_task` and `report_subagent_result`. A root MCP-enabled CLI delegates its own/unassigned ready task into a fresh managed session, inheriting profile, directory/worktree and pane size, with a separate pane positioned beside its parent without moving focus. An existing task ID reuses its worker. Ownership, dependencies and open handoffs are checked before mutation.
- The default-enabled policy instructs the parent to end its turn after delegation. Worker launch is synchronous only through PTY setup; completion is asynchronous. Attached workers cannot delegate/recruit. Limits are 1–20 active workers (default 20) and 40 retained workers per parent, centralized in `SubagentLimits`. A one-time settings migration replaces the legacy default of 3 with 20; other explicit limits survive. The persisted migration marker allows selecting 3 again afterward. Legacy settings did not distinguish an explicitly selected 3 from the old default. Workers share the directory and receive explicit scope rather than copied parent transcripts.
- `Store/SubagentPromotion.swift` promotes a worker when its parent is removed, when legacy saved state has no existing parent, or through the user's Promote to Main Conversation action. It clears parent/task-role markers and the generated initial worker prompt, preserving board tasks, ownership, evidence, approval state and exact provider resume identity. Tools and briefing files immediately reflect the main role. A running CLI is retained and shows a restart notice because its launch instructions and MCP catalog may be cached. Promotion is not exposed as an agent tool; attached workers cannot grant themselves delegation privileges.
- A result updates published task evidence, retains completion approval and queues a parent notification. Early worker exit blocks the task and releases its slot. Notifications persist even for stopped parents; published final task state is also a recovery outbox. An MCP tool result delivers them automatically during a provider turn. No unsolicited wake is claimed for an idle TUI; updates wait safely until its next AgentDeck tool call. `TaskEditorSheet` can launch newly created ready tasks; future/dependent tasks remain on the board.

## 11. Usage mini-window

- `Models/CLIUsage.swift` normalizes provider windows without inferring missing quotas. `Store/CLIUsageMonitor.swift` owns in-memory samples and refresh state, with an injectable reader for tests.
- Visible UI runs a cancellable 60-second refresh loop. Codex uses a bounded, short-lived stdio app-server process; Claude uses the default OAuth Keychain/file credential; Gemini uses its existing OAuth file and Code Assist health/quota calls. No model turns, credential refresh/write, onboarding, browser cookies, or transcript reads.
- Refresh attempt timestamps survive panel closure, so reopening within 60 seconds reuses the existing sample. Cancellation restores the prior timestamp for immediate retry; manual refresh bypasses freshness. `UsageCredentialCache` serializes/coalesces Claude credential reads on a utility task, caches only in memory for five minutes, and invalidates on HTTP 401/403.
- `NoninteractiveKeychain` combines `LAContext.interactionNotAllowed` with the legacy process interaction switch around a synchronous lookup, restoring the prior setting in `defer`. Apple's legacy login-keychain implementation ignores the modern context for ACL/unlock dialogs; if suppression cannot be established, no lookup runs. Credential ACLs and Keychain items are never modified.
- HTTP requests use ephemeral sessions, reject redirects and suppress cookie storage. No credentials, usage responses or account identifiers enter persisted state/MCP. Provider errors retain the previous timestamp/sample and mark it stale.
- Unsupported providers remain listed with explicit unknown usage/limits/reset. Custom profile/account environments are not assumed to match the default login.
